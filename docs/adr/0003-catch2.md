# 3. Write unit tests with Catch2

## Context

Maintainability is the client's main need: the team must be able to change the renderer
without breaking it, and explain any anomaly within the same day. We work test-first
(TDD), so we need a test framework that is quick to write tests with and gives
clear failure messages, including for floating-point values.

Options considered:

- **GoogleTest:** very widely used, but more boilerplate (fixtures, macros per type).
- **doctest:** very light and fast, but a smaller community.
- **Catch2 v3:** natural-language test names, one `REQUIRE` macro for most checks,
  matchers for floating-point comparisons (`WithinAbs`), and CTest integration.

## Decision

We use **Catch2 v3**, fetched by CMake with `FetchContent` and pinned to tag `v3.7.1`.

- Tests live in `tests/`, in folders that mirror `src/`, and are built into a single
  executable, `unit_tests`.
- `catch_discover_tests` registers each `TEST_CASE` with CTest, so `ctest` lists and
  runs them one by one.
- Floating-point values are compared with a tolerance (`WithinAbs(value, 1e-9)`),
  never with `==`, unless the result is exact.

## Status

Accepted

## Consequences

- Tests read like sentences ("a ray missing a sphere returns no hit"), which documents
  the behaviour.
- The first configure downloads and builds Catch2, which takes a little time.
- Each new test file must be added to `add_executable(unit_tests ...)` in
  `tests/CMakeLists.txt`.
- Catch2 v3 needs C++14 or later. That is no limit here, since we use C++20.
